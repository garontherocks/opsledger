# Phase 18 — bounded specialist comparison

Engineering experiment: direct single-agent baseline versus specialist-as-tool and full-context handoff. This optional module is not wired into product behavior. The existing direct workflow and default retrieval decision remain unchanged.

## Measured controlled comparison

Four reviewed synthetic cases (revision/outbox locks, workspace isolation, HTTP audience, absent evidence), two repetitions with reversed mode order, identical parent identity/evidence/checks/context hash in each pair. Each mode has eight outputs. The controlled provider supplies the known labels: all modes match eight labels, by construction. This verifies measurement plumbing and contracts; it cannot establish live semantic correctness, a calibrated eval score, or product value.

| Mode | Calls | Prompt characters | Fixture reported tokens | Local wall milliseconds |
| --- | ---: | ---: | ---: | ---: |
| Direct | 8 | 10178 | 240 | 2.804 |
| Specialists as tools | 24 | 34048 | 720 | 6.079 |
| Handoff | 24 | 32866 | 720 | 5.321 |

These timings are local protocol overhead, not model latency benchmarks. Tokens are controlled resource proxies, not inference billing or real resource consumption. Both specialist variants require three calls versus one; tools transfer all prior opinions while handoff transfers the previous opinion with the complete parent context. Neither mode demonstrates additional quality benefit in this controlled sample.

## Security and failure evidence

Five test groups passed locally: same identity/SHA/evidence; required failure blocks all provider calls; context omission/identity substitution/digest poisoning/extra authority fields rejected; malicious peer and disagreement inconclusive; outage/deadline/expiry/missing token metadata inconclusive. An initial test hashed a noncanonical fixture object and failed; it was corrected to use the runtime's existing canonical context representation. The runtime contract was not relaxed.

Parent-reviewed context is an experiment input, not an authentication endpoint. This module has no DB, runner, approval, shell, mutation, merge or release capability. Specialists retain the entire parent identity and expiry and never gain authority. Sources and peer prose remain untrusted. Maximum three calls, bounded text/context/token metadata and deadlines; expiry rechecked after awaits. Conflicting risk/status opinions produce an inconclusive result, never majority approval. A timed-out provider may finish independently; no result or authority is accepted afterwards. This is not an OS/process sandbox or exactly-once inference claim.

## Decision and limits

Reject default specialist adoption (ADR 0018): measured extra calls/context/operational contracts without demonstrated semantic benefit. Rejection completes the bounded engineering experiment; it does not certify live model quality. Real Ollama comparison remains an explicit M5 desktop/human review item, with no retuning or rerun of accepted M4 evidence. Fixtures are never substituted for live quality. Any later adoption requires reviewed paired semantic benefit sufficient to justify resource/security complexity.

Full required CI on this phase's resulting head remains the advancement gate. Evidence is generated by `m5:specialist-test` and `m5:specialist-fixture`, archived under `phase18-*`. No Phase 19 advancement on a failed gate. M5 human acceptance remains pending.

## Learning and architecture

Calling a specialist as a tool retains parent control and accumulates opinions. Handoff changes which prior opinion is visible but must preserve the parent evidence and identity tuple. Hash equality detects transport/context changes, not factual truth. Deterministic checks dominate all model outputs. More roles mean more untrusted input, failure points and latency; roles alone are not evidence of quality.
