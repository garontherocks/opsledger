# Phase 17 learning material — accumulated for the M5 checkpoint

n8n coordinates delivery and branches; the TypeScript service owns policy. A webhook is not a QA pass. The operator signs the strict run/workspace/SHA/time/operation/approval reference, n8n authenticates inbound delivery, and the service independently validates its scoped bearer and body signature. Neither a workflow editor nor a model output can grant an approval or release authority through this API.

A retry repeats the event ID and body. Durable dispatch state returns the authenticated prior receipt, rejects an altered body, and uses a lease for interrupted work. The report effect has its own transactional uniqueness and single-use approval boundary. Delivery can repeat; an acknowledged effect is reconciled after lost acknowledgement. This does not promise exactly-once transport.

An approval can be valid before an asynchronous SHA check and expired when that check returns. The new delegated service/event deadline must join the approval deadline before the SQL effect. The reproduced red regression and its correction demonstrate why a denied response after a write is insufficient. No model verdict may override a failed required check, invalid identity, different target, expired grant or approval.

Runtime readiness and external reachability are separate facts. The actual CI container returned health 200 internally and to the host through its isolated address while its published port was unreachable. Changing the host's owned-container connection preserves the internal network boundary. Blocked n8n registry DNS attempts are recorded; disabling telemetry alone is not an egress sandbox.

Community licensing and a self-hosted lab do not imply enterprise RBAC, unrestricted SaaS redistribution or a hostile-workflow sandbox. Workflow editing and host administration remain trusted. The native desktop profile binds loopback and is separate from the disposable isolated CI profile.

Questions to select for the single M5 Teach-Back: explain the two transport credentials versus the operator signing key; explain duplicate delivery versus a unique transactional effect; explain why the delegated deadline is checked at the effect boundary; identify which authority remains in TypeScript and which n8n actually holds. Controlled failures available: forged signature, failed required check, expiry during SHA revalidation, acknowledgement loss and isolated-network port reachability.
