# Phase 8 — Ingestion and semantic retrieval

Engineering scope complete: optional ranked semantic runbook search alongside keyword search; no generation or operational tools. Direct local embedding capability and PostgreSQL pgvector exact cosine search avoid a separate vector service or premature ANN/reranker. Explicit editor reindex/purge controls are independent of query generation.

Plain runbook Markdown is treated as inert source text, not rendered HTML or executable instructions. The deterministic chunker bounds 10,000-character immutable bodies to at most 16 overlapping chunks (1,000 characters with 120 overlap), preserving UTF-16 body offsets and surrogate pairs. This is not a PDF/URL ingestion service. Chunk metadata includes source/version/content hash, model/digest, fixed 768 dimensions and chunk-v1-768 index version. No credentials or model weights are stored.

Published current versions only: SQL joins apply workspace/current-publication/content-hash/model/digest predicates and active membership. Filters apply before ranking. No database connection is held during embedding. Index writes recheck editor membership and source revision in a transaction; invalid vectors/counts, stale changes and outages abort without partial replacement. Withdrawal/new publication removes obsolete chunks through a database trigger. Reader cannot index/purge. Generation and embeddings are independently off by default; synthetic nonproduction lab and exact digest are required.

Validation: lint/typecheck/build; 36 unit checks; integration 74 total, 73 pass and one inherited native-row-lock skip; independent retrieval suite 10 pass; semantic browser flow pass with zero retries. Browser proved source literal rendering, indexed retrieval, purge and keyword fallback.
